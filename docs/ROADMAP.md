# BuyJudge 로드맵

## 현재 상태

현재 구현 완료:

- GitHub 저장소 구축
- Streamlit 웹앱 배포
- yfinance 기반 데이터 수집
- 빠른 필터
- 유사사례 분석
- 위험차단
- 눌림대기
- CSV 결과 저장
- 웹 화면 확인

## v0.6 — 화면 사용성 개선

목표: 개발자용 표를 사용자용 판단 화면으로 바꾼다.

작업:

- 매수후보/눌림대기 카드 우선 표시
- 위험차단/통계부족은 접힌 영역으로 이동
- 원화/달러 포맷 적용
- 판정 이유 짧게 요약
- `지금 매수 가능`, `눌림 오면 관심`, `현재가 추격금지` 문장 표시
- 상세 표는 하단으로 이동

완료 기준:

- 웹 화면만 보고도 후보와 이유를 이해할 수 있어야 한다.

## v0.7 — 종목군 확장

목표: 유사사례 부족 문제를 줄인다.

작업:

- 한국 반도체/바이오/2차전지/로봇/방산/원전 종목군 확대
- 미국 ETF/빅테크/반도체 종목 확대
- universe 파일을 섹터별로 분리 검토
- 기본 universe와 확장 universe 구분

완료 기준:

- 주요 관심 종목에서 유사사례 0건이 줄어야 한다.

## v0.8 — 유사사례 엔진 개선

목표: 억지 유사사례를 줄이고, 정말 닮은 흐름을 찾는다.

작업:

- 가격 모양과 거래대금 가중치 분리
- 같은 테마/같은 시장/같은 자산군 비교 옵션
- 유사도 기준 자동 완화/강화 실험
- 유사사례 결과의 대표 차트 기간 저장
- 상승확률뿐 아니라 평균 최대하락도 더 강하게 반영

완료 기준:

- top_cases가 납득 가능한 사례로 보여야 한다.

## v0.9 — 매매 플랜 생성

목표: 후보가 떴을 때 뭘 해야 하는지 자동 문장화한다.

작업:

- 1차/2차/3차 분할매수 가격
- 포지션 사이징
- 손절가
- 1차 익절/2차 익절
- 잔여 보유 조건
- 매수 금지 사유 문장화

완료 기준:

- 후보마다 실행 가능한 매매계획이 나온다.

## v1.0 — 가상매매 기록

목표: BuyJudge가 실제로 의미 있는지 검증한다.

작업:

- 매수후보 발생 시 가상 진입 기록
- 이후 5일/10일/20일 결과 추적
- 승률, 평균수익, 평균하락, MDD 집계
- 판정별 성과 비교

완료 기준:

- 최소 1~2개월 가상매매 결과가 쌓인다.

## v1.1 — 알림

목표: 웹에 들어가지 않아도 후보를 알 수 있게 한다.

작업:

- Telegram/Discord 알림
- 매수후보/눌림대기만 알림
- 위험차단은 알림 제외
- 전일 대비 판정 변경 시 알림

완료 기준:

- 의미 있는 후보만 스마트폰으로 온다.

## v1.2 — 뉴스/재료 반영

목표: 가격/거래대금/차트 통계에 재료 점수를 보조로 붙인다.

원칙:

- 뉴스만으로 매수후보 승격 금지
- 뉴스 점수는 보조 가점
- 과열 뉴스는 오히려 위험 플래그

작업:

- 종목명 기반 뉴스 수집
- 키워드 분류
- 호재/악재/과열 키워드 분리
- 뉴스 점수 0~10점

완료 기준:

- 재료가 있으면 설명에 표시되지만, 리스크 기준을 뚫지는 못한다.

## v2.0 — 자동주문 검토

조건:

- 가상매매 성과 검증
- 리스크 관리 검증
- 매수후보 빈도 안정화
- 손절/익절 로직 검증

원칙:

자동주문은 마지막이다. 분석기가 검증되기 전에는 연결하지 않는다.
